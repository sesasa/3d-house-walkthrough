# Property walkthrough — technical reference

**Reference property:** Danish Villa · **Baseline:** front-yard-attached-garage · **Documented:** 24 September 2026

## What the final project delivers

An interactive, furnished 3D house that runs as a static website. Visitors can walk between rooms, use the floor plan, compare reference photos, inspect fixed items, and view the front garden and street. Separate open-door and closed-door scenes preserve appropriate geometry, navigation and baked lighting. Exterior context includes the attached garage, rear depot, planting, paving and simplified street, scaled from the available evidence.

The priority is faithful architecture and readable, restrained presentation: door handing, window placement, cabinet dimensions and fixture locations take precedence over decorative detail or dramatic shadows. Dimensions combine floor-plan calibration, photographs, owner corrections and approximately aligned parcel/roof outlines. They are estimates, not a measured building survey.

## How it was made

```text
Photos + main floor plan + measurements + owner corrections
                           ↓
Photo-informed geometry, materials and navigation, authored in metres
                           ↓ source GLB + structured metadata
              ┌────────────┴─────────────────┐
              ↓                              ↓
Unreal Engine on RunPod           Blender/Cycles on RunPod
Editable scene, scale checks,     GPU diffuse-light baking
camera and lighting setup        → denoise → neutral colour grade
              ↓                              ↓
Archived Unreal project          Optimized GLB + lightmaps
                                             ↓
                            Precomputed room reflection probes
                                             ↓
                            Three.js website → visitor's GPU
```

The common source scene feeds both Unreal and Blender. **The browser lightmaps were generated by Blender/Cycles; they are not exported Unreal Lumen or Lightmass lighting.** The delivered website uses a calibrated web renderer, so it is not a pixel-identical Unreal render. Reconstruction was authored and checked against the photographs and plan; no automatic photogrammetry, Gaussian Splatting or image-to-3D training system was used.

## What RunPod did, and why

RunPod supplied an NVIDIA L4 GPU with 24 GB VRAM for development work: preparing the Unreal scene and running the expensive diffuse-light calculations and denoising. This moved production work off the laptop and allowed lighting to be calculated ahead of time. Source files, tools and editable production artifacts were retained on a persistent volume and final archives were downloaded locally.

The final recorded status of both production Pods is **EXITED**. This is the saved delivery state, not a fresh cloud status check. Visitors do not need those Pods. Stopping compute does not remove the persistent volume or any storage charges.

## What the browser computes

The browser downloads the optimized scene and precomputed lighting. It uses the visitor's integrated or discrete GPU to draw geometry and evaluate materials and view-dependent reflections. It does not calculate full indirect lighting, stream Unreal video or contact a RunPod rendering server. Room reflection probes load as needed; high detail also uses planar bathroom mirrors.

Each door pose has 14 baked diffuse lightmaps and eight room reflection probes. The model is approximately **29 MB** and its lightmaps **17 MB** per pose, before other assets; the full distribution ZIP is approximately **219 MB**, containing both variants and supporting files. Only the active pose loads. Compressed download size is different from GPU memory: decoded lightmaps alone occupy about **188 MiB per pose**, with additional memory needed for geometry, materials and reflections.

Measured locally on Intel Iris Xe at 1200 × 900, continuous movement achieved approximately **56–59 FPS** in the three benchmark rooms. The recorded local load was 2.23 seconds; this does not predict public-network loading or performance on every device. Both poses passed navigation, door geometry, room spawn, photo/inventory and mobile-layout checks with external network access blocked and no recorded browser errors.

## Deployment and future reuse

Host the contents of `output/browser/` on a static HTTP(S) host, keeping relative asset paths intact; `?embed=1` supports embedding. No Unreal installation, paid GPU server or inference API is required for visitors. Walking is indoors; the street and garden are presented through exterior views and indoor sightlines.

The reusable result is a proven authoring, baking, optimization and validation workflow. Another house needs its own evidence, dimensional calibration, opening schedule and geometry. Missing surfaces cannot be recovered exactly from sparse photos. Static lighting also means significant geometry, furniture, door-pose or lighting changes require a new bake; hiding furniture can leave its baked shadows behind.
